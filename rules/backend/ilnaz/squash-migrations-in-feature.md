# Склейка миграций в feature-ветке

**Когда применять:** в feature-ветке до merge в `development` появилось несколько `makemigrations`-файлов **на одну модель** (например, 0004 добавил поля, 0005 поправил `related_name` по ревью).

**Правило:** склеить в одну до merge.

**Шаги:**

```bash
# 1. Откатить
docker compose exec app_metrica python3 manage.py migrate <app> <предыдущий-номер>

# 2. Удалить файлы миграций, которые надо склеить (0004_*.py, 0005_*.py)

# 3. Сгенерировать новую — Django соберёт все накопленные изменения
docker compose exec app_metrica python3 manage.py makemigrations <app>

# 4. Применить
docker compose exec app_metrica python3 manage.py migrate <app>
```

**Когда НЕ склеивать:**
- Миграция уже в development/main — склейка = переписывание чужой истории.
- Миграции **разных моделей** или **разных модулей** — пусть остаются отдельными.
- Data-миграция вперемешку со schema — склейка добавляет риска; обсудить с ревьюером.
- Если требуется снос данных — отменить склейку, [[never-drop-db]] важнее.

**Почему:** «две миграции на одну модель в рамках одной фичи — это шум в истории» (Руслан, MCA-320). Ревьюер не должен следить за тем, как состояние модели приходило к финалу пошагово. Связано: [[no-handwritten-migrations]], [[never-drop-db]].
