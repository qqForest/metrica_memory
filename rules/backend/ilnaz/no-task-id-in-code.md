# Никаких MCA-XX в коде

**Когда применять:** при написании комментариев, docstring'ов, переменных, имён классов/функций, миграций, тестов — везде в коде Metrica Backend.

**Правило:** упоминания `MCA-XX` (или любого другого идентификатора Tracker-задачи) **запрещены целиком и полностью** в коде. Это касается:
- комментариев (`# MCA-170: ...`)
- docstring'ов (`"""Test for MCA-170."""`, `"""... (MCA-170)"""`)
- названий тестов (`test_mca_170_...`)
- сообщений в `raise Exception(...)` с упоминанием задачи
- имён миграций

Где номер задачи уместен: commit message, заголовок PR, ветка (`feature/MCA-XX-...`), описание PR.

**Пример:**

```python
# Плохо
# MCA-170: запрет смены локации, если есть активные смены
if self.instance.shifts.filter(deleted_at__isnull=True).exists():
    raise ScheduleException(...)

"""Тест — PATCH /schedules/{id}/ запрет смены establishment (MCA-170)."""

# Хорошо — описывает поведение, не задачу
# Запрет смены локации, если в расписании есть активные смены
if self.instance.shifts.filter(deleted_at__isnull=True).exists():
    raise ScheduleException(...)

"""Тест — PATCH /schedules/{id}/ запрет смены establishment при наличии смен."""
```

**Почему:** код переживает задачи в трекере. Через год задача MCA-170 закроется, тред в Трекере уйдёт под фильтр «решённое», ссылка превратится в шум — а комментарий останется засорять файл. Контекст изменения принадлежит истории git (commit + PR), а не самому коду. Связь «строка → задача» находится через `git blame` → commit message → PR.

Связано: [[no-existing-text-rewrites]] (тот же дух — код не место для проектных мета-данных), [[review-code-not-pr-meta]] (PR-мета не должна влиять на оценку кода).
