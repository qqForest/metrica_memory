# Не переписывать существующие тексты косметически

**Когда применять:** при расширении уже работающего кода в Metrica Backend, если по пути встречается существующая русская строка (текст ошибки, `summary`/`description` Swagger, verbose_name, комментарий).

**Правило:**

- **Косметическую подмену** существующих строк — не делать. «Косметика» = переформулировка, синоним, мелкое уточнение, которое **не несёт новой информации, отсутствующей где-либо ещё в системе**.
- **Подмена допустима**, когда после расширения функционала старый текст становится **буквально неверным** (вводит фронт/клиента в заблуждение) и нигде больше про новое поведение не сказано. Тогда новый текст добавляет реальную информацию.
- Если сомневаешься — спроси у пользователя.
- Новые строки (в новом коде, в новых функциях) — пиши как считаешь нужным, это правило их не касается.

**Пример:**

На MCA-312 при добавлении CSV-ветки в `loader/`:

```python
# loader/services/fabric/manager.py: get_parser_class — fallback
# Косметика: «Неизвестный тип/формат» вместо существующего «Неизвестный тип загрузчика».
# Нет новой информации для пользователя — оставить как было.
detail = f'Неизвестный тип загрузчика: {loader_type}'

# loader/views.py: Swagger summary
# Реальная информация: про CSV-формат больше нигде в схеме API не сказано.
# Расширить — допустимо.
summary='Скачать шаблон метрик (xlsx / csv)'   # было: 'Скачать Excel-шаблон метрик'
```

**Почему:** на MCA-312 я подменил оба текста разом. Пользователь поправил дважды: сначала откатил оба ((1) «зачем менять русский текст? переиспользуй»), потом вернул Swagger ((2) «если про CSV нигде не указано, лучше оставить, головой думай»). Граница не «никогда не трогай» — а **косметика vs новая информация**. Karpathy §3 (хирургические правки): каждая изменённая строка должна напрямую соответствовать запросу пользователя. Косметическая подмена существующего текста — это **не** часть запроса. Расширение, отражающее новый функционал, — часть.
