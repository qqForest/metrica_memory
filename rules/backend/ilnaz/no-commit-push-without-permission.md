# Не коммитить и не пушить без явного разрешения

**Когда применять:** после любых правок в коде, даже мелких (переименование файла, дополнение тестов). Auto mode правило **не** отменяет.

**Правило:** показать diff/summary и **дождаться явного «коммить» / «пушь»**, не подразумевать согласие из контекста. Push в shared remote всегда требует явного подтверждения. **Не предлагать коммит/пуш даже как опцию** в конце ответа (фразы вроде «хочешь — закоммичу?», «осталось сделать commit + push» запрещены) — пользователь сам решит, когда коммитить. Закрытие задачи — это «готово, изменения в working tree», а не «готово к пушу».

**Исключение:** пользователь явно говорит «закоммить и запушь» или вызывает скилл `/pr-metrica` / `/commit` (сам по себе подразумевает коммит).

**Почему:** на MCA-231 в auto mode я закоммитил правки тестов и запушил в открытый PR без спроса — сильное недовольство. Пользователь сам контролирует когда что коммитить и когда отправлять в shared remote. Контекст «несколько раз пользователь сам делал коммиты в той же сессии» = сигнал контролировать процесс лично, а не разрешение действовать вместо него.
