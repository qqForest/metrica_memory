# Без юнит-тестов сервисов

**Когда применять:** при написании тестов для новой функциональности.

**Правило:** только API-тесты через `BaseTestCase` (HTTP-запросы). Не создавать файлы вида `tests/test_*_service.py` или `{app}/tests/test_*_service.py` с прямыми вызовами сервисных классов.

**Почему:** API-тесты покрывают бизнес-логику через реальные эндпоинты — слой больше, гарантия выше. Юнит-тесты сервиса дублируют это и устаревают быстрее каждого refactor'а. См. [[shared/test-patterns-crud]].
