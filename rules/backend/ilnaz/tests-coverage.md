# Покрытие scope в тестах

**Когда применять:** при написании тестов на ViewSet со scope-системой (`ScopedViewSetMixin`).

**Правило:** покрывать все 3 кейса видимости для каждой роли:

1. Основная локация — вижу / могу редактировать.
2. Неосновная локация — вижу / **не** могу редактировать.
3. Чужая локация — **не** вижу.

Для каждого action — позитивный (админ МОЖЕТ на свою) **и** негативный (админ НЕ МОЖЕТ на чужую/неосновную) сценарии.

Для `list`/`retrieve` прокидывать фикстуру «чужой» записи и проверять `not in ids`.

**Почему:** без реальных фикстур в БД тесты не доказывают корректность фильтрации. `assert len == 2` без третьей записи в БД — пустая проверка: фильтр мог и не отработать, а просто не было что фильтровать. Не ждать замечаний на ревью — сразу думать о полноте.
