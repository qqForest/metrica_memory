# Порядок тестов в файле

**Когда применять:** в каждом `tests/<app>/test_*.py`.

**Правило:**

```
200 / 201 / 204  →  400  →  401  →  403  →  404
```

Внутри 404: сначала scope-404 (`_soft_deleted`), потом not-found-404 (`_missing`).

**Пример:**

```python
async def test_delete_204(...): ...                 # 204
async def test_delete_204_for_import(...): ...      # 204
async def test_delete_401(...): ...                 # 401
async def test_delete_403(...): ...                 # 403
async def test_delete_404_soft_deleted(...): ...    # 404 scope
async def test_delete_404_missing(...): ...         # 404 not-found
```

**Дополнительно:**
- Несколько 200-кейсов идут подряд **в начале** (между ними любой порядок).
- Имя теста должно совпадать с проверяемым HTTP-кодом — `_404` не должен ассертить `400`.
- Не наследовать порядок из соседнего test-файла, если тот написан по-старому. Сверяться с правилом, не с образцом.

**Почему:** 401/403 — про **доступ**, 404 — про **наличие записи**. 404 ниже, потому что цепочка проверок до него не доходит, если permission/queryset отсеяли раньше. 400 — авторизованный юзер с невалидным payload, идёт выше 401/403 (auth уже прошла). На MCA-320 Руслан повторил «401, 403 выше 404» три раза. Связано: [[shared/test-patterns-crud]].
