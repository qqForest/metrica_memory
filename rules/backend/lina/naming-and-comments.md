# Имена и комментарии

## Имена

- Полные, без сокращений: `start_datetime`, `effective_start_time`, `time_slot`, не `start_dt`, `eff_start`,
  `ts`. Тривиальность кейса не оправдание.
- Без `_` в начале имени — нигде, не только во ViewSet/Serializer.
- Занятые слова под другой смысл не брать: `scope` — доступ ALL/TEAM/OWN, `action` — DRF `self.action`.
  Дискриминатор rate-limit — `endpoint_kind`, не `scope`.
- Сотрудник в новом коде — `user`, `user_ids`, не `profile` (решение ревьюера). Поля моделей не трогать.
  Исключение: где уже есть `self.user` как автор запроса, сотрудник остаётся `profile`.

## Docstring и комментарии

- Docstring — одна строка по сути: `"""Денормализованные datetime начала и окончания смены."""`. Без «когда
  заполняется / где используется», без `:param`/`:return`, даже если рядом многострочное
  легаси.
- `help_text` на поля моделей не писать, хватает `verbose_name` (Руслан, MCA-631).
- Прозу — по-русски, без англицизмов («в каждой строке», не «на каждой row»). Идентификаторы как есть.
- Комментарий объясняет смысл, а не повторяет имя функции или вызова.
- **Номер задачи (MCA-XXX) в коде — никогда.** Исключение — `# TODO: удалить после MCA-XXX`.

**Почему:** контекст задачи живёт в трекере и PR; имя — контракт, комментарий — для того, что имя не выразит.
