# Стиль сложных ORM-запросов — эталон `annotate_roster`

**Когда применять:** queryset собирается из нескольких аннотаций, подзапросов, фильтров и prefetch.

**Эталон:** `shifts/services/work_shift_services.py` → `annotate_roster`. Перед сложным запросом открыть его.

1. **Каждая часть выражения — своя переменная**, формула читается сверху вниз, а не из матрёшки внутри
   `annotate`.
2. **Цепочка методов — в скобках, точка в начале строки, отступ 4**, источник первой строкой:

   ```python
   shift_qs = (
       shift_qs
       .select_related('schedule__establishment', 'tag__color')
       .annotate(shift_hours=Round(plan_hours, 2))
   )
   ```

3. **Один длинный вызов — аргументы отступом 4, набиты до предела строки, висячая запятая**, скобка на своей
   строке. Без выравнивания по открывающей скобке.
4. **Условные части — последовательными присваиваниями** в ту же переменную, не одним ветвистым выражением.
5. **Итог — в переменную, `return` отдельной строкой.**

**Если выражение не собирается:** не говорить «не работает». PostgreSQL умеет `date + time` и
`interval * scalar`, Django — арифметику с `F()` и `timedelta`; обычно нужен `output_field` через
`ExpressionWrapper`. Тесты на SQLite такое не доказывают — проверять SQL на PostgreSQL.

**Почему:** сложные запросы читают чаще, чем пишут; единая раскладка снимает спор о скобках и переносах.
