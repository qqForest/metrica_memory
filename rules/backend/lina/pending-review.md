# Черновой review в GitHub

**Когда применять:** ревью чужого PR через черновой review (`POST /pulls/{n}/reviews` без `event`, состояние
PENDING).

**Правило:** черновик — не публикация: комменты видит только автор ревью и отправляет сам кнопкой Submit.
Заводить черновик — только по прямой просьбе. Ради правки текста review не пересоздавать: REST API не умеет
PATCH pending-комментов, а DELETE+POST затирает правки, внесённые параллельно в браузере. Вместо этого
сказать, какие комменты теперь расходятся с кодом.

**Почему:** однажды пересоздание review затёрло ручные правки.
