# Переиспользовать фикстуры — не плодить копии

**Когда применять:** перед добавлением новой `@pytest.fixture` или фабричной функции в `tests/fixtures/<app>.py`.

**Правило:** сначала проверить, нет ли уже подходящей. Иерархия предпочтений:

1. **Использовать существующую как есть** — если её данных хватает.
2. **Передать `data={...}` в существующую фабрику** — если разница в 1–2 полях.
3. **Создать объект прямо в тесте** через ту же фабрику — если кейс одноразовый.
4. **Новая фикстура** — только если объект встречается в нескольких тестах **и** существенно отличается по семантике.

**Чек перед добавлением:**

```bash
grep -l "def <model_name>" tests/fixtures/
grep "scope='function'" tests/fixtures/<app>.py
```

**Пример:**

```python
# Плохо — копия с минимальной разницей
@pytest.fixture(scope='function')
def admin_user(role_admin):
    return create_user({'username': 'admin', 'custom_role': role_admin})

@pytest.fixture(scope='function')
def admin_user_2(role_admin):
    return create_user({'username': 'admin_2', 'custom_role': role_admin})


# Хорошо — фабрика, второй юзер создаётся в тесте
async def test_two_admins_see_same_data(self, admin_user, role_admin):
    second_admin = create_user({'username': 'admin_2', 'custom_role': role_admin})
    ...
```

**Что **не** оправдывает новую фикстуру:**

- Другое имя/телефон/email без функциональной причины.
- Другая позиция при наличии параметра в фабрике.
- «Чтобы было два» — фабричный вызов в теле теста чище.

**Что оправдывает:**

- Объект с принципиально другой ролью/состоянием, используемый в 3+ тестах.
- Сложная цепочка зависимостей (юзер + локация + смена + клейм), повторяющаяся.

**Почему:** `conftest.py` загружается для каждого теста. Дубли с `scope='function'` пересоздают объекты заново, замедляют suite и захламляют namespace fixture-аргументов. Когда фабрика меняется (например, `User` обязательно требует новый параметр) — править надо в одной точке, не в десяти.
