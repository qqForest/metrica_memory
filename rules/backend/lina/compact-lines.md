# Компактные строки — не дробить до 119 символов

**Когда применять:** при написании или правке любого Python-кода.

**Правило:** если выражение помещается в **119 символов** — писать в одну строку. Не разносить вызовы и выражения на несколько строк ради «эстетики».

```python
# Хорошо
qs.filter(field1=val1, field2=val2)
datetime.combine(date, time, tzinfo=tz)
int((a - b).total_seconds() / 60)
log_action(ACTION, obj, user=None, request=None)

# Плохо — лишние переносы при влезающем выражении
qs.filter(
    field1=val1,
    field2=val2,
)

datetime.combine(
    date,
    time,
    tzinfo=tz,
)
```

Переносить **только** когда строка реально превышает 119 символов. Длинные импорты — через `\` (см. [[backend-style]]), не через скобки.

**Logger-сообщения:** короче, без лишних слов («, пропускаем», «, продолжаем»).

**Почему:** избыточные переносы снижают плотность информации на экране. То, что один человек видит как «структура», другой видит как «шум». Граница в 119 символов уже даёт читаемость — лимит ради того и есть. Источник лимита один:
`backend/.flake8`, `max-line-length = 119`; другого числа в проекте нет.
