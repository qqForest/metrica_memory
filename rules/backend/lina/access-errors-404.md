# Объект недоступен — 404 без перечисления id

**Когда применять:** объект из тела или пути запроса пользователю не принадлежит или не подходит.

**Правило:**

- Ответ — **404 с кодом `<СУЩНОСТЬ>_NOT_FOUND`**, не 400. Так сделано в `check_user_establishments`,
  `check_user_schedules`, `check_tenant_access`. Если чек-лист задачи требует 400, а ревьюер просит 404 —
  делаем 404, расхождение отмечаем в описании PR.
- **Id в `detail` не перечислять:** по перечислению видно, существует ли чужая запись. Все причины (нет
  записи, не та роль, нет доступа) склеиваются в один ответ.
- `field_name` передавать четвёртым аргументом `BaseAPIException`, иначе фронту не к чему привязать ошибку.
- Код заводить в `<app>/exceptions.py` приложения, чья это сущность (`USER_NOT_FOUND` — в `UserException`).

```python
raise UserException(UserException.USER_NOT_FOUND, 'Сотрудник не найден.', status.HTTP_404_NOT_FOUND, 'admin_ids')
```

**Почему:** 404 не выдаёт, что запись существует; единый ответ на все причины — тоже.
