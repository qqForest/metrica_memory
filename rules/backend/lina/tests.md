# Тесты — раскладка, фикстуры, что не тестировать

## Раскладка по файлам

- Сначала смотреть базовую ветку и соседние PR — это уклад, а не вкус.
- **От `development`:** файл на action (`test_schedule_retrieve.py`), кейсы доступа — в конец файла action.
- **Эпик прав (`development-permissions`):** файл на эндпоинт, кейсы доступа (`test_list_401`, `test_list_403`) —
  разделом `# ── доступ ──` в конце. Кейсы основной логики под суперюзером не трогать. Перед правкой структуры
  открыть `gh pr diff` ближайшего PR эпика.
- Файл уже есть (хоть с суффиксом `_access`) — дописывать в него.
- Новый параметр в нескольких эндпоинтах — кейсом в файле каждого ресурса, не файлом на параметр. Ассертом
  в существующий тест, если его ассерты не завязаны на точный состав данных.
- Кейсы, отличающиеся только пользователем, сливать в основной тест того же статуса.

## Сначала существующие тесты

Баг нашёлся (особенно за неверными фикстурами) — сначала починить фикстуры и прогнать существующие тесты
модуля без фикса. Часто они уже ловят регрессию. Новое — только на непокрытое, ассертом в существующий тест.

## Фикстуры — переиспользовать

Перед новой фикстурой `grep -l "def <model>" tests/fixtures/`. По порядку: взять существующую → передать
`data={...}` в фабрику → создать объект в тесте через фабрику → новая фикстура, только если объект нужен в
3+ тестах и отличается по смыслу (роль, состояние, длинная цепочка зависимостей). «Чтобы было два» и другое
имя без причины — не повод.

## Чего не делать

- Эффект изменения (деактивация, смена пароля) — одним сквозным сценарием через API под этим пользователем:
  `GET` 200 → `PATCH is_active=false` → `GET` 401 (ревью PR #457).
- На удалённое тестов не писать: ни 404/405 на выпиленные маршруты, ни `assert 'field' not in response`.
- Эффект пока не виден через API — тест не пишем. Загрузчики вида `load_logs()` в `tests/fixtures/` не
  заводить, там только фабрики `create_*`.
- Пакеты ради тестов (`fakeredis`) не тянуть — мокать (`MagicMock`, как redis в `BaseTestCase.login`).
- Безобидные варнинги не глушить `filterwarnings` — объяснять причину.
