# Без лишних проверок

**Когда применять:** при написании и правке условий, проверок на `None`/пустоту.

**Правило:**
- Одно и то же условие в нескольких местах — свести к одной проверке.
- Ветку под состояние, отсечённое выше по стеку (права, скоуп, валидация сериализатора, глобальная
  настройка), не писать. Поломка инварианта тогда вылезет 500-й, а не спрячется под значением
  по умолчанию.

Примеры:
- `in_schedule = user.role.in_schedule if user.role_id else True` — без роли скоуп `none`, до
  `get_own_queryset` дело не доходит; пишем `user.role.in_schedule`.
- Свой `list()` при глобальной пагинации: `page` никогда не `None`, ветки `if page is not None` /
  `else` мёртвые — остаётся `page` + `get_paginated_response`.

**Почему:** меньше шума — понятнее логика. Это Simplicity First: не обрабатывать невозможное.
