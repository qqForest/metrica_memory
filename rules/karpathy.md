# Четыре принципа Карпати

Адаптация [forrestchang/andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills) на русский. База для всех в команде.

## 1. Думай, прежде чем писать

**Идея:** не делай молчаливых допущений, проблемы и компромиссы выноси наружу.

- Перед реализацией явно сформулируй допущения.
- Если не уверен — спроси, а не угадывай.
- Если есть несколько интерпретаций — назови их все, не выбирай молча.
- Предлагай более простой путь, если он есть. Возражай, если просьба ведёт в тупик.

**Главное:** если что-то непонятно — остановись. Назови, что именно мутно. Спроси.

## 2. Минимализм первым

**Идея:** пиши минимальный код, решающий задачу — ничего спекулятивного.

- Не добавляй фичи сверх требований.
- Не делай абстракций для одноразового кода.
- Не вводи незапрошенную гибкость.
- Не обрабатывай ошибки для невозможных сценариев.

**Самопроверка:** сказал бы сеньор «это переусложнено»? Если да — переписывай.

## 3. Хирургические правки

**Идея:** трогай только то, что необходимо. Убирай только за собой.

При правке существующего кода:
- Не улучшай соседний код.
- Не рефактори работающие куски.
- Не меняй стилевые предпочтения, подстраивайся под существующий стиль.
- Если твои правки сделали ненужными импорты или функции — удали их.
- Но предсуществующий мёртвый код не трогай, если не просили.

**Тест:** каждая изменённая строка должна напрямую соответствовать запросу пользователя.

## 4. Цель → проверка

**Идея:** превращай размытую задачу в проверяемый критерий и крути цикл, пока он не выполнен.

- Размытое «почини баг» превращай в «напиши воспроизводящий тест, потом сделай его зелёным».
- Для многошаговой работы — короткий план с чекпойнтами верификации.
- Сильный критерий «готово» позволяет работать без постоянных уточнений; слабый — заставляет дёргать пользователя.
