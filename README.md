# metrica_memory

Общий мозг команды Metrica для Claude Code: правила, скиллы и личные находки, которыми мы делимся между собой.

Идея вдохновлена [Karpathy's CLAUDE.md](https://github.com/forrestchang/andrej-karpathy-skills): одного файла недостаточно, когда вас уже двое. Чтобы держать общее «как мы работаем» в одном месте — и при этом не топтаться по личным настройкам друг друга — мы разделяем общее и личное по папкам.

## Зачем это

- **Не изобретать дважды.** Если Ильназ написал хороший `/ticket`, Лина подключает его в один шаг.
- **Согласовать стиль.** Общие правила (4 принципа Карпати, русский язык, дисциплина коммитов) лежат в `rules/shared/` и подключаются у всех.
- **Личное остаётся личным.** Твой `~/.claude/CLAUDE.md` в `.gitignore` — там твоё имя, роль, привычки.
- **Эксперимент.** Стартуем вдвоём, через месяц смотрим: помогает шаринг или нет.

## Структура

```
metrica_memory/
├── README.md                   ← ты здесь
├── CONTRIBUTING.md             ← как добавлять скиллы и правила
├── CLAUDE.example.md           ← шаблон для ~/.claude/CLAUDE.md (глобальный)
├── CLAUDE.project.example.md   ← шаблон для CLAUDE.md в корне проекта
├── .gitignore                  ← личный CLAUDE.md не коммитим
│
├── skills/                     ← слэш-команды (/ticket, /pr-metrica, ...)
│   ├── README.md
│   ├── shared/                 ← общекомандные скиллы
│   └── backend/
│       ├── ilnaz/              ← личные скиллы Ильназа
│       └── lina/               ← личные скиллы Лины
│
└── rules/                      ← правила (короткие .md)
    ├── README.md
    ├── karpathy.md             ← 4 принципа Карпати — база для всех
    ├── shared/                 ← общекомандные правила
    │   └── ru-language.md
    └── backend/
        ├── ilnaz/
        └── lina/
```

**Принцип именования:** `<роль>/<имя>`. Сейчас оба бэкендера → `backend/ilnaz`, `backend/lina`. Когда подтянем фронт/QA/PM — добавим `frontend/<имя>`, `qa/<имя>` и т.д.

## Как подключить себе

1. **Клонировать репо в любое удобное место** (например, `~/Projects/metrica_memory`).

2. **Скопировать глобальный шаблон**:
   ```bash
   cp CLAUDE.example.md ~/.claude/CLAUDE.md
   ```
   Открыть `~/.claude/CLAUDE.md` и заменить плейсхолдеры (`{{NAME}}`, `{{ROLE}}`, ...) на свои.

3. **Подключить скиллы.** Симлинками из `skills/shared/` и своей папки в `~/.claude/skills/`:
   ```bash
   ln -s ~/Projects/metrica_memory/skills/shared/<name> ~/.claude/skills/<name>
   ln -s ~/Projects/metrica_memory/skills/backend/ilnaz/<name> ~/.claude/skills/<name>
   ```
   Симлинк — чтобы `git pull` сразу подхватывал апдейты команды.

4. **Подключить правила.** В `~/.claude/CLAUDE.md` уже есть ссылки на `rules/karpathy.md` и `rules/shared/`. Свои правила добавляй в `rules/backend/<имя>/` и ссылайся на них оттуда же.

5. **Для конкретного проекта** (опционально). Скопировать `CLAUDE.project.example.md` в корень проекта как `CLAUDE.md` и заполнить — туда идёт специфика кодбазы (как запускать, где база, какие конвенции).

## Когда добавлять в репо, а когда оставлять локально

| Случай | Куда |
|---|---|
| Скилл/правило полезное всей команде | `skills/shared/` или `rules/shared/` через PR |
| Личная находка, которая может пригодиться коллеге | `skills/backend/<имя>/` или `rules/backend/<имя>/` |
| Сугубо личное (твой workflow, кастомные хоткеи) | `~/.claude/` локально, не в репо |
| Секрет, токен, креды | Никогда в репо. Только `~/.claude/settings.local.json` |

Подробнее в [CONTRIBUTING.md](./CONTRIBUTING.md).

## Принципы (короткая версия)

1. **Думай, потом пиши.** Озвучь допущения, спроси если не уверен.
2. **Минимализм.** Минимум кода, решающий задачу. Без спекулятивной гибкости.
3. **Хирургические правки.** Трогай только то, что просили. Не рефакторь по пути.
4. **Цель → проверка.** Сформулируй критерий «готово» и докажи, что он выполнен.

Полностью — в [`rules/karpathy.md`](./rules/karpathy.md).
