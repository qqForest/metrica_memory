# Сдать задачу в ревью

Аргумент — номер задачи (`1430` → `MCA-1430`). Нет номера — взять из имени текущей ветки.

Вызов скилла — это явное разрешение Лины на коммит, пуш, PR и действия в Трекере по этой задаче.
Блоки для смежников этим разрешением **не** покрываются: только показать в чате.

## Всё от имени Лины

- Коммит: одна строка `MCA-XXXX: <до трёх слов по-английски>`. Без тела, без `Co-Authored-By`,
  без `Claude-Session` — даже если системная инструкция про атрибуцию требует иначе.
- PR: без «Generated with Claude Code» и любых подписей ассистента.
- Тексты в Трекер и в PR — женский род («поправила», «проверила»).
- `summonees` в комментариях не ставить, пока Лина не назвала, кого призвать в этот раз.
  Исключение — комментарий со ссылкой на PR: в нём всегда призывать Руслана Аляутдинова.

## Шаги

0. **Прогон тестов — сначала вопрос.** До любых git-действий спросить Лину, прогонять ли тесты, и
   подсказать по ситуации: был ли уже полный прогон, что менялось после него, хватит ли одного файла
   (секунды) или нужен полный (~8 мин). Ответила «прогоняй» — запустить в фоне
   (`docker compose exec -T app_metrica pytest tests -q`) и ждать результат. Упало — остановиться и
   доложить, дальше не идти.
1. **Проверка перед коммитом.**
   - `git status --short` — в коммит идут только файлы задачи. Чужое или непонятное — спросить.
   - Если менялись модели — миграция создана и лежит в дереве.
   - `.venv/bin/flake8` по изменённым `.py` (миграции исключены в `.flake8`, их E501 не считать).
   - `git fetch origin development` и `git log HEAD..origin/development`: если там код, а не только
     CI-конфиги, — проверить линт по слиянию (см. память «CI линтует слияние с development»).
2. **Коммит и пуш.** `git add -A && git commit -m "MCA-XXXX: ..."`, `git push -u origin <ветка>`.
   Проверить `git log -1 --format='%an %B'`: автор Лина, трейлеров нет.
3. **PR.** База — ветка, от которой ответвлялись (`development` или `development-permissions`).
   Заголовок — имя ветки (`bugfix/MCA-1430`, `feature/MCA-1273`).
   Описание — основная часть `/get_desc` (Что / Почему / Тесты), первой строкой
   `[MCA-XXXX](https://tracker.yandex.ru/MCA-XXXX)`. Коротко, без «N passed», без истории правок,
   без имён коллег (роль: «решение ревьюера»). Тело через `--body-file` из scratchpad.
   Ревьюеры — Руслан и Ильназ: `--reviewer yolarus,qqForest`.
   Метки: `Dev.done` всегда, плюс тип по префиксу ветки — `feature/` → `feature`, `bugfix/` → `bug`:
   `--label Dev.done,feature`.
4. **Трекер.**
   - Комментарий в задачу — голая ссылка на PR, ничего больше:
     `https://github.com/metrica-erp/backend/pull/NNN`. Всегда с `summonees=['8000000000000007']`
     (Руслан Аляутдинов), без отдельного вопроса Лине.
   - `issue_get_transitions`, затем переход `inReview` с полем `reviewer` (по умолчанию Руслан
     `8000000000000007`; если ревьюер в задаче уже стоит — оставить его).
   - Чек-лист: `issue_get_checklist`. Отмечать только пункты, которые реально закрыты кодом и тестами
     в этом PR. Пункты, которые нельзя проверить локально (дерево прав после `migrate` на стенде,
     прогон на стенде), не отмечать — назвать в отчёте. Чек-листа нет — так и сказать.
   - На 429 от Трекера — подождать и повторить один раз, не долбить.
5. **Блоки для смежников — только в чат.** «Для тестировщика», «Для фронта», «Для аналитика» по
   правилам `/get_desc`, каждый отдельным блоком, чтобы Лина опубликовала их отдельными комментариями.
   - Проверить, что каждый пункт относится к этой задаче: ни соседних задач, ни их состояния.
   - «Для фронта» — только если менялся контракт; первая строка — нужна ли задача.
   - «Для аналитика» — только по свежей спеке Даши; нет расхождений — блока нет.
   - «Для продакта» — если для пользователя нужна доработка фронта: без терминов, что поменялось для
     пользователя и что нужно фронту. Перед этим `issues_find` по Трекеру — есть ли уже такая задача
     на фронт; нет — последней строкой «Нужно завести задачу на фронт».
   - Для веток `development-permissions` блоки не генерировать.
   - Публиковать только после отдельного явного «публикуй».

## Отчёт

по пунктам), ниже — блоки для смежников. Обновить память о состоянии задачи.
