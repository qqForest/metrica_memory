# Сводка для дейлика

## 1. Окно

- Конец — сегодня 10:30 МСК (07:30 UTC). Начало — 10:30 МСК предыдущего рабочего дня.
- В понедельник предыдущий рабочий день — пятница: выходные входят в окно. Праздники не учитываются.
- Окно назвать первой строкой сводки: «с 24.10 10:30 по 27.10 10:30».

## 2. Кандидаты

`issues_find`, `fields: [key, summary, status, assignee, updatedAt]`:

```
Queue: MCA Assignee: me() Updated: >= "<дата начала окна>" "Sort By": Updated DESC
```

Только задачи, где исполнитель — Лина. Задачи без исполнителя и чужие не брать.

## 3. Что реально произошло — по истории, не по `updatedAt`

`updatedAt` двигают лайки, правки чек-листа и ночные обновления около 00:52 МСК без смены статуса — по нему задача
попадает в сводку ложно. Для каждого кандидата:

- `issue_get_changelog(field: status)` — переходы статуса с временем и автором; в окно попадает
  переход, у которого `updatedAt` внутри окна. Нет перехода в окне — задачу из сводки убрать.
- Перевела Лина или ревьюер/тестировщик — писать, кто: «перевела в Ревью», «Руслан принял».
- Комментарий считать комментарием, только если он есть в `issue_get_comments`.
  `IssueCommentReactionAdded` в истории — это лайк, не комментарий.

## 4. Что решено задачей

Источники: описание задачи (`issue_get`), заметка `memory/mca-XXXX-sostoyanie.md` и связанные заметки
из `MEMORY.md`, если есть.

Строка на задачу: что изменилось для пользователя — «раньше нельзя было X, теперь можно», «перевели
на Y». Без терминов из кода (полей, эндпоинтов, кодов ответа, имён классов), как фраза для дейлика.
В конце — статус: «в Готово», «на ревью», «взяла в работу».

## 5. Нюансы

Отдельным блоком, у каждого — ключ задачи: «MCA-1290: …».

Брать только то, что **ни с кем не обсуждалось**. Не нюанс:
- решение, записанное в заметке как «решили с Дашей/Русланом», «ответ …»;
- то, о чём уже написано смежникам в комментарии задачи (тестировщику, фронту, продакту);
- вопрос, по которому в задаче уже ждут ответа (`pendingReplyFrom`).

Нюансов нет — блок не выводить.

## 6. Формат

```
Сводка для дейлика за период с 26.10 10:30 по 27.10 10:30:

- MCA-1290 — организации сотрудника теперь подтягиваются из его локаций, вести их отдельно не нужно. Приняли, в «Готово».
- MCA-1520 и MCA-1521 — уведомление сообщает приложению, что произошло; переход больше не ломается при смене текста. Обе на ревью, задачу фронту завели.
- MCA-1481 — взяла в работу: менеджеры смогут ставить смену задним числом, на дату до добавления сотрудника в локацию. Это просили с прода.

Нюансы, которые ни с кем не обсуждались:
- MCA-1290: Владелец без привязки к локации останется без организации в шапке. В черновике тех.спеки регистрации она у него есть.
```

Задачи одного PR — одной строкой. Сводку только показать, никуда не публиковать.
